## Observations

1. **Makefile `install` target as spec was unambiguous.** It fully
   enumerates 11 shipped paths (binary + desktop + icon + license + 6
   completions + man), so translating it into a cargo-deb `assets`
   array was a direct 1:1 mapping with no design judgment calls needed
   - low ambiguity task.
2. **build.rs's `ci-release` feature gate was the one non-obvious fact**
   needed to make the target functional: without it, `completions/`
   and `man/` never materialize on disk (they're gitignored and only
   written when that feature is active). This was found by reading
   `build.rs` directly, not from any framework-provided doc - context-
   only arm gets no assistance here beyond what exploration surfaces
   and records in `.ai/notes.md`.
3. **AGENTS.md's generated project-context section was empty on
   arrival** (just the one-line description, "Populated by /explore.
   Do not edit by hand."); this run's `/explore`-equivalent pass (per
   its `SKILL.md`) had to be done manually per instructions before the
   task, which cost a few tool calls (probe.py, reading Makefile/
   Cargo.toml/build.rs/.github workflows) that a context arm with a
   pre-populated map would have skipped.
4. **No local toolchain at all** (no `cargo`, no GTK4 headers) meant
   "tests and lint must pass" (AGENTS.md protocol item 2) could not be
   honored locally in the literal sense; the only real verification
   available was TOML-parse validity (`tomllib`) plus the prescribed
   docker gate. The framework's protocol doesn't address an
   environment where the project's own build tooling is absent -
   reasonable given this is a generic scaffold, but worth flagging: an
   autonomous run has to fall back to "best verification available"
   rather than the literal instruction.
5. **`.ai/notes.md`'s "append decisions/gotchas, commit `.ai`"
   discipline worked smoothly** for a single-file, mechanical change:
   one explore commit, one task-notes commit, no friction, no spec/
   build machinery invoked (correctly, since the task explicitly
   forbade it and the change is small and self-contained).
