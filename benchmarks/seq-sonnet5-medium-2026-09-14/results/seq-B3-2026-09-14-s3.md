## Observations

1. The working tree already contained unrelated, uncommitted work before this task
   started (a `rename_column`/`rename-column` feature, plus what appears to be a
   seeded bug in the FTS content-lookup SQL in `db.py`, changed from
   `content="{}"` to `content=[{}]`). This was left untouched per instructions;
   the final diff therefore mixes that pre-existing work with the new drop-column
   work, which is expected and reflected as-is in the diff above.

2. `drop_column()` was implemented to check column existence in Python first
   (raising `sqlite_utils.db.AlterError` and never issuing the `ALTER TABLE`
   statement) rather than relying on SQLite's own error for a DROP of a
   nonexistent column. This guarantees the "leave the table unchanged" requirement
   by construction rather than by accident of SQLite's transactional behavior, and
   mirrors the existing `add_foreign_key` pattern for the same kind of check.

   diff noise (different `--fmt` choice lists and a `[integer|...]` vs
