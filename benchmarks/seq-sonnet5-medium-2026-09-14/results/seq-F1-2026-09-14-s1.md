## Goal
`tests/test_fts.py::test_enable_fts_replace_handles_legacy_bracket_quoted_content_table`
fails. `Table.enable_fts(..., replace=True)` raises
`sqlite3.OperationalError: table "books_fts" already exists` when the
existing FTS5 table was created with legacy SQLite bracket-quoted
identifiers (`CREATE VIRTUAL TABLE [books_fts] USING FTS5 ([title],
content=[books])`) instead of double-quoted ones.

Root cause: `Table.detect_fts()` (sqlite_utils/db.py) builds a `LIKE`
query to find a table's associated FTS shadow table by matching
`content="<table>"` in `sqlite_master.sql`. It has two `LIKE` clauses,
`:like` and `:like2`, intended to cover both quoting styles, but both
are set to the *same* double-quote pattern
(`content="{}"`.format(self.name)) — the bracket-quoted variant
(`content=[{}]`) is never checked. A third clause
(`tbl_name = :table AND sql LIKE '%VIRTUAL TABLE%USING FTS%'`) does not
help either: `tbl_name` for the FTS5 virtual table row is the FTS
table's own name (`books_fts`), never the content table's name
(`books`), so it can't match by content-table name at all.

Consequently, for a legacy bracket-quoted FTS table, `detect_fts()`
returns `None`, `disable_fts()` silently skips dropping the old FTS
table (`if fts_table:` guard), and the subsequent
`CREATE VIRTUAL TABLE "books_fts" ...` in `enable_fts()` collides with
the still-existing legacy table.

## Observations

1. **Root cause was a copy-paste duplication bug, not a logic bug.** In
   `Table.detect_fts()` (`sqlite_utils/db.py`), the `like` and `like2` LIKE
   patterns were both set to the identical double-quote pattern
   (`content="{name}"`), so the bracket-quoted legacy form
   (`content=[{name}]`) was never checked. This silently broke
   `disable_fts()` for any database containing an FTS5 table created with
   bracket-quoted identifiers (a common legacy/older-SQLite-tool style), which
   in turn broke `enable_fts(replace=True)` with a confusing
   `table already exists` error rather than a clear "can't detect FTS table"
   message. The fix is a one-line change (swap one of the two duplicate
   values), verified against `sqlite_utils/db.py:2765-2787`.

   cause.** Running the full suite before finalizing turned up
   `tests/test_tracer.py::test_with_tracer` also failing on a fresh checkout

   sent to the tracer. It expected `like` to hold the bracket-quoted pattern
