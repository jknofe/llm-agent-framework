## Task

`tests/test_fts.py::test_enable_fts_replace_handles_legacy_bracket_quoted_content_table`
failed. Root cause: `Table.disable_fts()` (called from
`enable_fts(..., replace=True)`) relies on `Table.detect_fts()` to find the
FTS shadow table to drop before recreating it. `detect_fts()` only matched
`content="<table>"` (double-quote quoted) in `sqlite_master.sql`; an FTS
table created with legacy SQLite bracket-quoting (`content=[books]`) was not
detected, so `disable_fts()` silently no-op'd and the subsequent
`CREATE VIRTUAL TABLE books_fts ...` failed with
`sqlite3.OperationalError: table "books_fts" already exists`. Fixed by
repurposing the previously-duplicate `like2` LIKE argument (it was bound to
the exact same double-quote pattern as `like` - dead duplication) to match
the bracket-quoted form instead.

## Goal
`Table.disable_fts()` (called from `enable_fts(..., replace=True)` when the
existing FTS index needs to be recreated) relies on `Table.detect_fts()` to
find the associated FTS shadow table. `detect_fts()` only matches
`content="<table>"` (double-quote quoted) in `sqlite_master.sql`. An FTS
table created with SQLite's legacy bracket-quoting style
(`content=[<table>]`, e.g. by an older sqlite-utils version, hand-written
SQL, or another tool) is not detected. `disable_fts()` silently no-ops
(does not drop the stale FTS table), so the subsequent
`CREATE VIRTUAL TABLE ... books_fts ...` in `enable_fts()` fails with
`sqlite3.OperationalError: table "books_fts" already exists`. Fix
`detect_fts()` to also recognize bracket-quoted `content=[<table>]`, so
`enable_fts(replace=True)` can recreate an FTS index that was originally
created with bracket quoting.

## Observations

   recreate-vs-reuse decision.** `enable_fts(replace=True)` correctly
   decided a stale FTS index needed replacing (schema string comparison
   caught the bracket-vs-double-quote mismatch), but the cleanup step

   than the comparison step, so it couldn't find what to delete. This kind
