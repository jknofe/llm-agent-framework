## Observations

1. The repository's `rename-table` CLI command / `Database.rename_table()` API
   made for a clean, direct template: same argument shape (`PATH TABLE
   NEW_NAME` -> `PATH TABLE COLUMN NEW_NAME`), same `--ignore` option, same
   try/except-to-`ClickException` wrapping. Only real design decision was
   where the "column already exists" guard should live - I put it in
   `Table.rename_column()` itself (raising the existing `AlterError`) rather
   than depending on SQLite's own `OperationalError` for a duplicate column
   name, so the check happens before any SQL executes and the table is
   provably left unchanged (SQLite's native `ALTER TABLE ... RENAME COLUMN`
   would itself refuse the operation too, but pre-validating avoids relying on
   that engine-specific behavior and gives a consistent, code-base-native
   exception type).
2. `docs/cli-reference.rst` is cog-generated from the CLI's own `--help`
   output. Running `cog -r` in this sandboxed environment regenerated the
   *entire* file because the installed `tabulate` version's `--fmt` choices
   list differs from whatever version produced the file currently committed
   in the repo (extra choices like `asciidoc`, `colon_grid`, `rounded_grid`,
   etc. that this environment's tabulate doesn't have). That produced 134
   lines of unrelated churn across every command's `--help` block. I reverted
   that regeneration and instead hand-added only the two pieces cog would
   have added for a real run (the `refs` dict entry and the new command's
   help block, copied verbatim from a direct CLI invocation), keeping the
   diff to the 20 lines actually attributable to this feature. This is a
   pre-existing environment/dependency-pinning gap unrelated to the task.
