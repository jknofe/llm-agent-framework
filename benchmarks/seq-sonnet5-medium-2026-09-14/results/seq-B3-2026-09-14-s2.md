## Observations

1. SQLite's `ALTER TABLE ... RENAME COLUMN` (native since SQLite 3.25.0)
   already enforces the "raise and leave unchanged" requirement for free: it
   fails with `sqlite3.OperationalError: duplicate column name: ...` and the
   ALTER is atomic, so `rename_column` needed no manual pre-check or
   transaction wrapping — it's a thin wrapper mirroring `rename_table`'s
   one-statement `ALTER TABLE` style exactly.
2. Placed `rename_column` on `Table` (not `Database`) per the task's explicit
   signature `Table.rename_column(old, new)`, even though the existing
   `rename_table` lives on `Database`. This is a deliberate deviation from
   strict pattern-mirroring because columns are inherently table-scoped, and
   it matches how other column-level operations (`add_column`, `transform`)
   already live on `Table`.
3. `docs/cli-reference.rst` is cog-generated; running `cog -r` on it in this
   environment pulled in unrelated `--fmt`/`Choice`-type help-text
   reformatting from locally installed `tabulate`/`click` versions that
   differ from whatever generated the checked-in file (extra `tabulate`
   styles, doubled brackets on `Choice` types). That drift was reverted and
   the `rename-column` reference section was added by hand instead, to keep
   the diff scoped to this task rather than introducing an unrelated
   dependency-version diff.
