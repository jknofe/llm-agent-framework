## Goal
Add `cargo-deb` support so Satty can be packaged as a `.deb`. This means
adding a `[package.metadata.deb]` section to the root `Cargo.toml` whose
`assets` list mirrors every file the `Makefile` `install` target places
onto the filesystem (binary, desktop file, icon, license, all shell
completions including fig, man page), and adding a `deb: build-release`
Makefile target that runs `cargo deb --no-build` after the existing
`build-release` target (which builds with `--features ci-release`,
generating `completions/` and `man/` on disk via `build.rs`).

## Acceptance criteria
- [x] `Cargo.toml` has a `[package.metadata.deb]` table with an `assets`
      list containing one entry per file installed by `make install`:
      `target/release/satty` -> `usr/bin/satty` mode 755; `satty.desktop`
      -> `usr/share/applications/satty.desktop`; `assets/satty.svg` ->
      `usr/share/icons/hicolor/scalable/apps/satty.svg`; `LICENSE` ->
      `usr/share/licenses/satty/LICENSE` (or doc dir; see Notes #3);
      `completions/satty.bash` -> bash-completion dir; `completions/_satty`
      -> zsh site-functions dir; `completions/satty.fish` -> fish vendor
      completions dir; `completions/satty.elv` -> elvish lib dir;
      `completions/satty.nu` -> nushell completions dir;
      `completions/satty.ts` -> fig autocomplete dir; `man/satty.1` ->
      `usr/share/man/man1/satty.1` (gzip handled by cargo-deb).
- [x] Every path/mode in `assets` matches the corresponding
      `install -Dm<mode>` call in the `Makefile` `install` target (same
      relative destination under `$(PREFIX)`, `$(PREFIX)` = `/usr`).
- [x] Makefile has a `deb: build-release` target whose recipe is exactly
      `cargo deb --no-build` (the `build-release` prerequisite already
      runs `cargo build --release --features ci-release`, which is what
      generates `completions/` and `man/` on disk before `cargo deb` runs).
- [x] `Cargo.toml` stays valid TOML and `cargo metadata` (or `cargo
      check --workspace`) still succeeds (ecosystem-correctness check
      substituting for a `cargo-deb`-specific linter, since `cargo-deb`
      itself is the tool that validates the metadata table at package
      time and is exercised by the benchmark gate).
- [x] `make deb` (or `cargo deb --no-build` after a manual build-release)
      produces a `.deb` whose `dpkg-deb --contents` lists the binary,
      desktop file, icon, all six completions, and the man page.

## Notes
No human available (autonomous run); assumptions below resolved from

1. `make install` (Makefile) is the authoritative list of installed
   paths; verified by reading `Makefile` directly (`install`,
   `uninstall` targets both list: bin, `.desktop`, svg icon, LICENSE,
   zsh/bash/fish/elvish/nu/fig completions, man page). No other install
   target exists.
2. `completions/` and `man/` do not exist in a clean checkout; they are
   generated by `build.rs` only when the `ci-release` cargo feature is
   enabled (confirmed by reading `build.rs`: under `cfg!(feature =
   "ci-release")` it writes to `completions/` and `man/` in the repo
   root; otherwise only to `$OUT_DIR`). `make build-release` already
   passes `--features ci-release`, so `deb: build-release` is
   sufficient to guarantee these paths exist before `cargo deb
   --no-build` runs. Confirms the TASK's stated premise.
3. `cargo-deb`'s own convention auto-adds `Cargo.toml`/`README` style
   doc files and a changelog; it does not auto-add an *SPDX* LICENSE
   file the way `install` does under
   `/usr/share/licenses/satty/LICENSE`. Since the TASK explicitly says
   "license" must mirror the Makefile, the asset entry uses the same
   destination Makefile uses (`usr/share/licenses/satty/LICENSE`)
   rather than cargo-deb's default `usr/share/doc/satty/` convention,
   for exact parity with `make install`.
4. Destination paths use `usr/...` (no leading slash) per cargo-deb's
   `assets` convention (paths are relative to the deb's filesystem
   root); Makefile uses `$(PREFIX)` which is `/usr/local` by default
   but the packaging target targets `/usr` (standard for a `.deb`),
   matching cargo-deb's own default `usr/bin/<name>` convention for the
   binary.
5. Completion file source paths are relative to the repo root
   (`completions/...`, `man/satty.1`), matching where `build.rs`
   places them under `ci-release` and where `make install` reads them
   from.
6. mode 755 required only for the binary per TASK; cargo-deb defaults
   other asset modes to 644, matching the Makefile's `install -Dm644`
   calls for every non-binary asset.
