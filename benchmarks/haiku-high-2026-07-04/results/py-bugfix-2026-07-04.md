## Task
Fix the failing test: `tests/test_fts.py::test_enable_fts_replace_handles_legacy_bracket_quoted_content_table`

## Specification
The test failed because `enable_fts(replace=True)` couldn't handle FTS tables created with legacy bracket-quoted identifiers (e.g., `[books_fts]` instead of `"books_fts"`). The `detect_fts()` method only searched for double-quoted identifiers in the FTS table schema, so it returned `None` when encountering bracket-quoted tables. This prevented `disable_fts()` from dropping the old table before attempting to create the new one, resulting in "table already exists" error.
