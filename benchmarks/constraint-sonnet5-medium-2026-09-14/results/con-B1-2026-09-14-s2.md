   `Table.rename_column`, and a column logically belongs to a `Table`, so
   the new method was placed on the `Table` class (next to `add_column`)
   rather than mirroring the exact class of `rename_table`. This is a
   deliberate deviation from "mirror rename_table" in favor of the more
   sensible OO placement and the literal method name given in the task.
2. The "raise and leave table unchanged" requirement was satisfied for
   free by ordering: both the "old column must exist" and "new column must
   not already exist" checks happen against `columns_dict` *before* any
   `ALTER TABLE` is executed, using the pre-existing `AlterError` exception
   (already used by `add_foreign_key` for an analogous "No such column"
   case) rather than inventing a new exception type.
3. `docs/cli-reference.rst` is cog-generated (per `docs/contributing.rst`).
   Editing only the `refs` dict by hand and then running
   `cog -r docs/cli-reference.rst` (in the same Python 3.12 docker image
   used for tests, since `cogapp` isn't installed on the host) regenerated
   the `rename-column` section with the correct `--help` text automatically
   - avoided hand-transcribing CLI help output that could drift from the
     real `--help` text.
