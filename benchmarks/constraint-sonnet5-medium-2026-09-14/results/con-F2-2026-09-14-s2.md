## Observations

1. Read both `AGENTS.md` and `.ai/notes.md` before starting. `AGENTS.md`'s generated
   project-context section was directly load-bearing: it states "Column renames/drops: use
   `ALTER TABLE ... RENAME COLUMN` and `ALTER TABLE ... DROP COLUMN` directly, even though
   older code in this repo does it the other way" - this ruled out mirroring the `transform(rename=...)`
   machinery (which does a full table rewrite via `CREATE TABLE ... rename mapping ... INSERT`) even
   though that pattern already exists in `db.py` for column renaming. Without that line I would likely
   have reached for `transform()` since it's the only existing column-rename code path. `.ai/notes.md`
   at read time only contained an unrelated FTS `detect_fts()` bug note - nothing applicable to this
   task, so nothing from it was used other than confirming there was no prior art/gotcha for column
   renaming to build on.

2. SQLite's native `ALTER TABLE ... RENAME COLUMN` already raises `sqlite3.OperationalError` for both
   failure modes the task cares about ("no such column" and "duplicate column name: X") and leaves the
   table's schema untouched on failure (verified interactively: `PRAGMA table_info` unchanged after a
   rejected rename). That meant `Table.rename_column()` could be a single `self.db.execute(...)` call,
   exactly mirroring `Database.rename_table()`'s shape, with no extra Python-side existence/collision
   checks needed to satisfy "must raise and leave the table unchanged" - the engine already guarantees
   it. Recorded this as a decision in `.ai/notes.md` since it explains a design choice (no `AlterError`
   precheck like `add_foreign_key` uses) that isn't obvious from reading `db.py` alone.

3. The CLI command required updating three docs surfaces, not just one: `docs/python-api.rst` (new
   "Renaming a column" section, Python API), `docs/cli.rst` (new "Renaming a column" section, CLI
   narrative docs), and `docs/cli-reference.rst`, which is a `cog`-generated file embedding live
   `--help` output per command keyed off `cli.cli.commands` plus a hand-maintained `refs` dict mapping
   command name -> doc anchor. Missed the third initially since it looks auto-generated end-to-end; had
   to add a `"rename-column": "cli_renaming_columns"` entry to the `refs` dict and re-run
   `cogapp -r docs/cli-reference.rst` inside the container (needs the package installed for
   `CliRunner().invoke(cli.cli, [...])` to work) before `cogapp --check` (the project's doc-check
   command per `AGENTS.md`) would pass.
