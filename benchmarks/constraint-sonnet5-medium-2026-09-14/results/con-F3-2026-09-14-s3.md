## Observations

1. **Read both `AGENTS.md` and `.ai/notes.md`; both were used.**
   `AGENTS.md`'s generated project-requirements block stated the exact rule
   that decided the implementation: "Column renames and drops use
   `ALTER TABLE ... RENAME COLUMN` and `ALTER TABLE ... DROP COLUMN`
   directly, even though older code in this repo does it the other way"
   (the "other way" turned out to be `Table.convert()`/`_convert_multi()`
   calling `self.transform(drop=...)`, confirmed by grep). It also gave the
   exact test commands (`pytest`, `cog --check README.md docs/*.rst`), which
   is why `cog -r` was run to regenerate `docs/cli-reference.rst` and
   `cog --check` was verified green before finishing.
   `.ai/notes.md` had a directly on-point entry: "`Table.rename_column()` is
   a thin wrapper around `ALTER TABLE ... RENAME COLUMN`... SQLite's native
   RENAME COLUMN is atomic: renaming onto an existing column name raises
   OperationalError and leaves the table's columns/rows untouched, no manual
   rollback needed... CLI `rename-column` catches OperationalError and gates
   it on --ignore." This was used directly as the design and even the error
   behavior for `drop_column`/`drop-column` — it meant no experimentation
   was needed to confirm DROP COLUMN's atomicity/error-on-missing-column
   behavior; the note transferred verbatim to the new column-drop code path
   and its tests (mirrored the "leave the table unchanged" assertions from
   `test_rename_column` in both `tests/test_create.py` and
   `tests/test_cli.py`).

2. **The rule about `transform()` shaped what NOT to do.** AGENTS.md's other
   rule ("`Table.transform()` rewrites the whole table... New public methods
   must never call it") ruled out the tempting shortcut of implementing
   `drop_column` via `self.transform(drop=(column,))`, which is what the
   existing internal helpers (`convert`/`_convert_multi`) already do. Without
   that explicit rule, mirroring the nearest existing "drop a column" code in
   the repo would have been the obvious (and here, wrong) move.

3. **Doc-generation coupling was non-obvious from the task alone.**
   `docs/cli-reference.rst` is built by a `cog` block that maps CLI command
   names to `:ref:` anchors via a hardcoded `refs` dict; a new CLI command
   needs an entry there or `cog --check` (part of the project's required
   commands, per AGENTS.md) silently fails after the command is added. This
   wasn't stated anywhere except by reading the cog script embedded in the
   .rst file itself — AGENTS.md pointed at the check command but not at this
   internal wiring, so it was found by grepping for how `add-column`/
   `rename-column` show up in the docs tree before writing new prose.
